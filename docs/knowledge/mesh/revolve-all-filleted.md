# Revolve_All_Filleted: проекция скругления

Исходный проект: `tests/data/mesh-regression/Revolve_All_Filleted.dom3d`.
SHA256: `2A570ECACA17CEF3CA62DF716DA112E0569F0C027DEDEB984668A72CDEBE596D`.

При Mesh Quadro без SLX, Density 0.35, поверхность 37 (нумерация с нуля)
создавала 21 треугольник и 13 квадов, 6 компонент и рёбра длиной до 89.4.
После сварки всего тела оставалось 25 открытых рёбер.

Это поверхность вращения обрезанной образующей. Неограниченная проекция
`GeomAPI_ProjectPointOnSurf` с градиентным поиском возвращала для части точек
неверную стационарную проекцию. Последующее разворачивание периодического U
превращало скачки между ветвями в самопересекающийся UV-контур.

Для `GeomAbs_SurfaceOfRevolution` проекция теперь использует UVBounds грани
и `Extrema_ExtAlgo_Tree`. Небольшое расширение параметрических границ (1e-5)
позволяет проецировать граничные точки, округлённые до float. Остальные типы
поверхностей сохраняют прежний способ проекции.

При Density 0.35 исправленная поверхность содержит 40 квадов, одну компоненту,
максимальное ребро 9.415. Всё тело после сварки замкнуто: 0 открытых рёбер.

Дополнительно на Density 0.50 исходная сетка имела несовпадающие узлы на
стыках F4/F9/F11. У B-spline углового скругления с вырожденной четвёртой
стороной три реальные стороны теперь получают общий бюджет узлов до
синхронизации с соседями. Это устраняет разрывы при повышении плотности.

`RevolveAllFilletedQuadro` проверяет обратное преобразование граничных точек
через UV (ошибка менее 2e-4), связность всех поверхностей, квадро-полосу
скругления без рёбер через тело и замкнутость сваренной сетки. Плотности:
0.25, 0.35, 0.50, 0.80, затем повторная 0.35.
Все эти проверки прошли. На исходной реализации тест падает на несвязной
сетке. Отдельный тест `SpherePoleQuadro` падает и до изменений с сообщением
`Sphere and Cap use different boundary node counts`.
