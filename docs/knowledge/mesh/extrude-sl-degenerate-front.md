# Extrude_SL: вырожденный остаточный фронт в UV

Статус: `Внедрено`  
Дата фиксации в Wiki: 2026-09-02  
Связанный компонент: `ContourQuadrangulator3DCoat`

## Краткий вывод

Ранее исправленный случай из серии пользовательских Quadro-моделей.
Входная UV-линия и её триангуляция были корректны. Щель возникала уже в
квадрангуляции, до пересчёта UV в XYZ: продвижение фронта создавало почти
нулевую полоску вдоль прямой границы. После остановки сглаживание расширяло
её в видимый разрыв. На некоторых плотностях повторяющиеся попытки занимали
около 35 секунд.

## Исправление и проверки

- Проверяется ориентированная площадь каждого остаточного кольца с допуском,
  соответствующим точности исходных float-координат.
- Знак углового векторного произведения проверяется без подстановки нормали
  `+Z` для почти нулевого вектора.
- Неизменный набор неуспешных кандидатов не повторяется до лимита итераций.
- Сняты прежние ограничения Density 0.50 для сложных тел и 27 точек на ребро.
- Fill Contour вынесен из обработчика UI в `Tools_Mesh3D`; диагностический
  вход — одна полилиния в исходных UV, без умножения U на радиус цилиндра.

Тест `ExtrudeSlQuadro` проверяет оба тела файла и рост плотности до 1.00.
`ToolsMesh3DFillContour` проверяет отдельную 60-узловую UV-линию в обычном и Raw
режиме: сохранение границы, замкнутость патча, положительную площадь, полное
покрытие контура и масштабирование. Подробные условия и данные сохранены
в [описании тестов](../../../tests/data/mesh-regression/README.md).

```powershell
ctest --test-dir build -C Release -R 'ExtrudeSlQuadro|ToolsMesh3DFillContour' --output-on-failure
```

## Связанный, но другой случай

[Box_Min_Box_Filled](box-min-box-filled-boundary.md) тоже проявляется щелью.
Однако там есть отдельная ошибка передачи разбитой CAD-дуги и невырожденный
остаток из шести узлов. Его нельзя исправить одним лишь запретом почти
нулевых фронтов.
