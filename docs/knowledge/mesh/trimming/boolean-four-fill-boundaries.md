# Boolean-4_All_fill: подмена наружного ребра и ложное дно

Дата: 2026-09-02. Компоненты: `Solid.cpp`, `SurfaceFace.cpp`,
`ContourQuadrangulator3DCoat.cpp`.

Статус: описанные дефекты дна исправлены; остаются отдельные варианты
разрезания SLX, перечисленные ниже. Файл не объявляется полностью исправленным
для всех плотностей и всех режимов.

## Модель и воспроизведение

`Boolean-4_All_fill.dom3d`, Boolean Union, 148 поверхностей. Плита с двумя
короткими сквозными отверстиями, одним длинным сквозным отверстием и ребром.
Показанные пользователем режимы: SLX 0.30 / 0.70, обычный Quadro 0.35.
Исходный файл не изменён; копия находится в `tests/data/mesh-regression`.

Большие плоские грани 12 и 120 лежат в y=0 и y=2. На каждой должно быть
пять циклов: наружный прямоугольник и четыре внутренних границы.

## 1. Почему отверстие становилось дном

`sync_trim_lines_from_regular_mesh` использовал геометрическое сопоставление,
если у получателя не находилось общего OCCT-ребра с донором. При этом у обеих
сторон могли быть достоверные, **разные** топологические рёбра.

Для длинного ребра 29.6 допуск составлял 1% длины, то есть 0.296. Он превышал
расстояние между соседними сторонами скругления sqrt(0.2²+0.2²) = 0.282843.
Два наружных ребра поверхности 12 подменялись чужими:

- x=21.8, y=0 → x=22, y=0.2;
- x=0.2, y=0 → x=0, y=0.2.

Наружный контур переставал замыкаться. Сборщик отбрасывал его четыре открытых
фрагмента; крупнейшее из оставшихся отверстий становилось «наружным контуром».
Поэтому одновременно исчезала плоскость и появлялась заглушка длинного отверстия.
Это происходило до SLX, в обоих режимах Quadro, а не при UV → XYZ.

Исправление: известные несовпадающие OCCT-рёбра никогда не сопоставляются
по близости. Геометрический поиск остаётся для отсутствующих метаданных.
Дополнительно плоская грань отвергает неполный набор замкнутых контуров:
число циклов не может быть меньше числа CAD wires. Периодические поверхности
с их специальной сборкой шва этим правилом не затрагиваются.

## 2. Незакрытые фронты из шести и восьми узлов

На поверхности 120 при обычном Quadro 0.35 оставался шестизвенный фронт:
одна наружная вершина и пять узлов около скруглённого угла отверстия.
Две выпуклые ячейки не помещались, поэтому прежний `closeSixNodeFront` оставлял щель.

Теперь сначала проверяются прежние выпуклые разбиения, затем — две простые
четырёхугольные ячейки, допускающие вогнутый угол. Для каждой выбирается
диагональ с двумя положительно ориентированными треугольниками; порядок
вершин поворачивается под эту диагональ. Граничные узлы не добавляются
и не перемещаются. Это локальное завершение фронта, не переход всей грани
к треугольной сетке и не ограничение плотности.

На обычном Quadro 0.70 обнаружился аналогичный остаток из восьми узлов.
`closeSmallEvenFront` отделяет допустимую четырёхугольную часть и закрывает
оставшиеся шесть узлов. Проверка остальных вершин запрещает отрезать часть,
содержащую другие узлы фронта. После сварки этот случай также замкнут.

## 3. Несогласованная сетка в полюсах

На высокой плотности некоторые сферические скругления получали, например,
подготовленную границу из пяти узлов, но сетку 5×3. При обратной проекции XYZ
долгота полюса неоднозначна; направление ребра в UV определялось неверно.

`adjust_mesh_quantities_from_prepared_edges` теперь использует родную OCCT
pcurve для определения направления и диапазона ребра. Число узлов берётся
из подготовленной границы. При отсутствии pcurve сохранён прежний способ.
На SLX 0.70 это убрало оставшиеся 48 открытых рёбер без увеличения допуска сварки.

После получения реальных граничных рядов регулярных сеток требуется ещё раз
согласовать противоположные и общие рёбра. Иначе B-spline-скругление может
получить пять узлов с одной стороны, три с другой, а его сосед продолжит
использовать три. Согласование повторяется до устойчивых количеств перед
окончательной перестройкой сеток; применяется только максимум уже запрошенных
количеств, а не искусственное изменение Density.

## Проверки и границы результата

При регрессионной проверке проявилась ошибка памяти в `SplitFaceByVar5`:
ссылка на исходную грань использовалась после `faces_.push_back`, который мог
перераспределить массив. Исходная грань теперь хранится как копия; добавлены
проверки индексов и четырёхугольной топологии обоих участников. Отдельный
`MeshVar5Reallocation` принудительно уменьшает вместимость массива перед
разрезом и проверяет восемь треугольников, площадь, связность и границу пары.

Регрессия `BooleanFourFillQuadro` проверяет восстановление плоских граней,
пять граничных циклов, площадь, классификацию ячеек по CAD и замкнутость
сваренной сетки. Для всех 148 поверхностей проверяется связность. Затем тест
намеренно смещает одно наружное подготовленное ребро: оба режима должны
отклонить неполный контур, а не заполнить крупнейшее отверстие.

Итоговая расширенная диагностика (проверки сварки и CAD-классификации):

| Режим | Density | Результат |
| --- | --- | --- |
| Обычный Quadro | 0.20, 0.25, 0.30, 0.35, 0.50, 0.70, 0.85, 1.00 | Замкнутая манифолдная сварка, 0 открытых рёбер |
| SLX | 0.30, 0.35, 0.70 | Замкнутая манифолдная сварка, 0 открытых рёбер |
| SLX | 0.20, 0.25, 0.50 | Отказ построения плоских граней при разрезании |
| SLX | 0.85 | 0 открытых рёбер, но нарушена манифолдность |
| SLX | 1.00 | 32 открытых ребра |

Автотест `BooleanFourFillQuadro` включает оба режима на 0.30, 0.35 и 0.70
и возврат к SLX 0.30 после плотной сетки. Остальные значения из таблицы проверены
отдельными диагностическими запусками. Эти проверки не меняют доступный
пользователю диапазон Density.

Финальный Release-прогон: **19 выбранных регрессионных тестов пройдены**
за 183 секунды, включая обе новые проверки, все ранее исправленные модели
и `MeshRegressionCorpus`. Это не утверждение о прохождении всего набора CTest.
Приложение `build/Release/Dom3D_Pro.exe` пересобрано.

**Оставшийся отдельный дефект:** расширенная диагностика обнаружила сбой SLX
на 0.20, 0.25 и 0.50. Необработанные сочетания касаний крупной ячейки и контура
доходят до `heal_closed_trim_boundary`; в многоугольнике появляется повторный
обход вершины или самопересечение. Затем `triangulate_mesh_ngons_in_xy` отвергает
грань. Это не подмена ребра и не ошибка полюса. Не маскировать сменой режима,
автоматическим повышением Density или удалением проверки триангуляции.

На SLX 1.00 перестроение завершается, но сохраняются 32 открытых ребра около
скруглений отверстий (поверхности 11/12/28/95/120/125). Нулевое число открытых
рёбер на других плотностях также следует проверять вместе с манифолдностью,
площадью и CAD-классификацией, а не считать достаточным критерием само по себе.

Диагностическая зацепка для 0.25: поверхность 12, ячейка 88, `VariantCut=0`,
три касания границы. После восстановления контура получался обход вида
`105,106,127,181,182,183,105,179,126,179`. Экспериментальный обработчик таких
касаний не решил все самопересечения и в рабочий код не включён.

```powershell
ctest --test-dir build -C Release -R BooleanFourFillQuadro --output-on-failure
```
