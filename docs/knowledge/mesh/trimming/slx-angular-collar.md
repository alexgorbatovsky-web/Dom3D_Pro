# SLX: схождение лучей воротника на угловом отверстии

Статус: `Внедрено`  
Дата фиксации: 2026-08-26  
Компонент: `CSurfaceFace::BuildFilledMeshWhithHoles(..., true)`

## Наблюдение

На угловом отверстии сам воротник создавался, но около одной вершины несколько
его рёбер сходились почти в один пучок. Визуально кольца присутствовали, однако
лучи между ними не расходились в соответствии со сторонами контура. Дефект
особенно заметен у несимметричных многоугольников, чей центр плохо описывает
локальную геометрию угла.

## Причина

Внешние кольца строились радиальным переносом каждой вершины от общего центра
отверстия:

```text
направление = вершина - центр всего контура
```

Такое направление корректно для окружности и близких к ней звёздчатых фигур,
но не связано с двумя сторонами конкретного угла. Кроме того, фактическая
граница после `TrimByPline` сшивалась с воротником по полярному углу относительно
того же центра. На нерадиальном контуре это могло неверно сопоставить вершины.

## Исправление

В [`src/solid/SurfaceFace.cpp`](../../../../src/solid/SurfaceFace.cpp) применены
три изменения:

1. Направление вершины нового кольца вычисляется по пересечению двух локально
   смещённых соседних сторон. Длина смещения ограничена шагом кольца: острый угол
   получает безопасный bevel и не создаёт длинный miter-шип.
2. Полученное кольцо принимается только при правильной ориентации и отсутствии
   самопересечений. Также сохраняются проверки наружного контура и соседних
   отверстий.
3. Сшивка колец больше не сортирует вершины по полярному углу. Начальная пара
   выбирается по геометрической близости, дальнейший zipper идёт монотонно по
   нормированной накопленной длине обоих периметров.

Дополнительно выбор фактической границы стал симметричным: недостаточно, чтобы
запрошенное кольцо находилось близко к найденной петле. Все вершины найденной
петли тоже должны оставаться локальными. Это не позволяет случайно сшить
воротник одного отверстия с дальней частью наружной границы или с другим
отверстием.

## Почему сохранено поведение круглых отверстий

Для правильного восьмиугольника локальная биссектриса совпадает с прежним
радиальным направлением. Ограниченная длина переноса оставляет доказанную
ширину воротника, поэтому исправление углового случая не увеличивает наружное
кольцо круглого отверстия и не ухудшает работу `TrimByPline`.

## Регрессионная проверка

В [`tests/CatalogImportTests.cpp`](../../../../tests/CatalogImportTests.cpp)
добавлено косое шестиугольное отверстие, малое относительно фоновой клетки.
Проверяются:

- успешное построение SLX с включённым воротником;
- отсутствие граней внутри отверстия;
- совпадение площади сетки с площадью OCCT-грани;
- отсутствие неманифолдных рёбер;
- отсутствие вырожденного пучка рёбер в локальной области воротника.

Фокусированный запуск:

```powershell
cmake --build build --target CatalogImportTests --config Release -j 4
.\build\Release\CatalogImportTests.exe --test-low-poly-quadro
```

## Граница решения

Исправлена геометрия воротника и его сшивка. Это не отменяет отдельного
исследования внутренних вариантов `CMesh3D::TrimByPline`, когда несколько точек
линии обреза попадают в одну крупную клетку.
