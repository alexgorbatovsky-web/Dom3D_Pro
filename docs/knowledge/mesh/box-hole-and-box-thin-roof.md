# Box_Min_Hole_And_Min_Box: почти совпадающие грани над вырезом

Статус: исправлена подготовка новых BOX/Cylinder на грани; исходный fixture сохранён.

## Исправление подготовки инструмента

**Актуальное правило:** по уточнению пользователя запас фиксирован — **0,001
единицы модели**, без зависимости от камеры. BOX/Cylinder сдвигают начало
против вытягивания на 0,001 и увеличивают модуль длины на 0,001, сохраняя
дальний торец. Старые значения `boolean.overlap`, включая экранные, при
перестроении геометрии игнорируются. Само открытие сохранённой BRep не меняет её.
Проверки с прежним значением 0,588 подтверждают применение нового запаса 0,001.

### Предыдущая реализация (заменена фиксированным запасом)

Для BOX и цилиндра, создаваемых на грани, viewport сохраняет `boolean.overlap`:
семь логических экранных пикселей, переведённых в единицы модели на глубине
точки размещения (минимум 0,01 для численной устойчивости при сильном увеличении).
Это экранный масштаб в плоскости камеры, а не проекция нормали на экран.
Сохранённый запас не пересчитывается при смене камеры или воспроизведении истории.

Начало инструмента сдвигается против направления вытягивания на этот запас;
модуль длины увеличивается на тот же запас. Дальний торец остаётся на заданной
дистанции от исходной базовой плоскости. При отрицательной высоте это выводит
режущий инструмент наружу, не меняя глубину кармана. Положительная высота также
сохраняет заданное положение торца при добавлении перекрытия для Union.
Свободные примитивы без `boolean.body_id` не получают запас.

Раньше RebuildShape уже сдвигал начало на фиксированные 0,01, но не увеличивал
длину. Поэтому прежнее утверждение о полном отсутствии сдвига было неточным.
Старые операции без сохранённого экранного запаса используют прежние 0,01,
теперь с компенсацией длины. Сохранённая готовая BRep-геометрия не исправляется
простым открытием файла: требуется повторное построение соответствующей операции.

Проверки: границы инструментов обоих знаков, сохранение 7-пиксельного запаса
из viewport и отсутствие крыши при ошибке базовой плоскости 1,90734863e-6.
Release-сборки CatalogImportTests и Dom3D_Pro успешны. Пройдены
`--test-boss-pocket`, `SolidPrimitiveTool` и `FacePrimitiveCut`.

Дополнение: `merge_saved_parameters` теперь сохраняет `boolean.body_id` и
`boolean.overlap`, которых нет среди видимых defaults. Иначе повторное
построение или открытие операции для редактирования теряло экранный запас.
Регрессия проверяет положительный объём Common для выступающих BOX/Cylinder,
один solid после Fuse и сохранение обоих торцов после восстановления истории.

Новая пользовательская версия без скруглений сохранена отдельно как
`tests/data/mesh-regression/Box_Union_Failed.dom3d`. Её CAD snapshot содержит
17 граней в одной компоненте смежности по общим CAD-рёбрам. Поэтому утверждение,
что именно эта сохранённая версия состоит из двух раздельных объёмов,
не подтверждено. Один снимок экрана не заменяет проверку CAD-связности.

Тело `Boolean Cut`, 11 граней. На пользовательском снимке видны полосы
над прямоугольным угловым вырезом рядом со сквозным круглым отверстием.

Исходные CAD-границы, до перестроения сетки:

- Верхняя грань F3: Z = 9,56146430969238.
- Потолок углового выреза F5: Z = 9,56146240234375.
- Зазор: 1,90734863e-6 единицы модели.
- CAD-ребро E5 имеет ту же длину; его tolerance = 1e-7.
- Топологический snapshot валиден, все 11 CAD faces валидны.

Это ненулевая тонкая перемычка в исходной CAD-геометрии, а не доказанный
разрыв после согласования полилиний. Почти совпадающие грани объясняют
наблюдаемый рисунок как вероятный z-fighting. GPU/depth-buffer отдельно
не исследован. Нельзя автоматически удалять E5 или объединять грани:
размер больше CAD tolerance; нужно определить желаемую семантику Boolean
при почти касающемся инструменте.

Диагностическое перестроение Mesh Quadro при Density 0,50, SLX выключен:
3500 вершин после сварки, 3500 квадро-клеток, 0 открытых рёбер,
manifold=1. Допуск сварки 0,00202026 значительно больше толщины перемычки;
поэтому успешная замкнутость после сварки не доказывает сохранение этой детали
и не считается исправлением дефекта.

Команды:

```powershell
CatalogImportTests.exe --diagnose-project-quadro tests/data/mesh-regression/Box_Min_Hole_And_Min_Box.dom3d 0.50
CatalogImportTests.exe --snapshot-project-boundary tests/data/mesh-regression/Box_Min_Hole_And_Min_Box.dom3d "Boolean Cut" output/box-hole-and-box/cad-boundary.json
```

Артефакты в `output/box-hole-and-box`: before/after JSON (через
`DOM3D_PIPELINE_DUMP`), CAD snapshot, лог и OBJ до/после сварки
(через `DOM3D_WELD_DUMP`). Код алгоритма не менялся.
