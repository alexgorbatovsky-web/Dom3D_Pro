# Procedural Fine Plaster

В Material Editor нажать **Procedural Plaster…**, включить **Use Procedural
Fine Plaster**. Редактирование применяется сразу. Кнопка Close закрывает
параметры; назначение материала объектам остаётся штатным действием редактора.
Готовый исходный материал находится в категории **Procedural → Fine Plaster**.

Размеры Grain / Macro / Micro / Pore заданы в миллиметрах. Scale одновременно
масштабирует структуру; Relief усиливает нормаль без изменения геометрии.
Seed детерминированно меняет рисунок. High quality добавляет микрозерно.
Base Color, Roughness и их небольшие вариации управляют внешним видом.
Metallic процедурной штукатурки всегда равен нулю.

Reference image служит визуальным образцом рядом с OpenGL-предпросмотром и
не используется в вычислении материала. Для первого материала ориентир —
светлая мелкозернистая штукатурка. Настройки не восстанавливаются из фотографии
автоматически.

## Реализация

- `ProceduralMaterial.h`: параметры и диапазоны; `Material::plaster` включает
  процедурный источник. Обычные материалы по умолчанию выключены.
- `ProceduralPlasterShader.h`: непрерывное трёхмерное поле высоты, производные
  нормали, коррелированная шероховатость, слабая cavity-AO. Результат поступает
  в существующее PBR-освещение `CMesh3D`, включая окружение.
- Координаты берутся из геометрии перед камерным преобразованием. Камера
  не перемещает поле; изменение положения самих вершин меняет участок поля.
  Миллиметровый масштаб не зависит от UV или количества полигонов.
- Экранные производные ослабляют частоты меньше пикселя. Preview пропускает
  микрозерно, High включает его. Рельеф не меняет силуэт и не выдавливает меш.
- `ProceduralMaterialIO.h`: JSON version 1 в XML-атрибуте `proceduralPlaster`.
  Проект, библиотека и drag-and-drop сохраняют параметры и seed. Старые файлы
  без атрибута сохраняют прежнее поведение. Неверный блок в XML даёт
  предупреждение и базовый материал.
- `MaterialPreviewGL.cpp`: сфера через тот же `QtSceneRenderer` и mesh shader,
  отдельный OpenGL-контекст, framebuffer, кэш изображений до 64 MiB.
  Переключения между сценой и предпросмотром используют отдельные кэшированные
  программы шейдера. Размер сферы — 50 мм, чтобы мелкое зерно было различимо.

## Экспорт PBR-карт

Кнопка **Export PBR Maps…** в окне штукатурки открывает настройки: разрешение
256–4096, ширина и высота участка в миллиметрах, начало XYZ. Выпекается участок
плоскости XY с текущими Seed, Scale и качеством. Затем выбирается родительская
папка; экспорт создаёт новый каталог, не заменяя существующие файлы.

Пакет содержит BaseColor.png (sRGB), NormalGL.png (+Y), NormalDX.png (−Y),
Roughness.png, AO.png, Metallic.png (чёрная) и Height.png (16-bit grayscale).
Кроме BaseColor, карты являются данными, без цветокоррекции. Height хранит
физическое смещение: `mm = (sample16 / 65535 − 0.5) × (heightMaxMm − heightMinMm)`.
Диапазон и все параметры записаны в manifest.json. Освещение в карты не входит.

FinePlaster.d3mat можно импортировать как обычный текстурный материал: цвет,
нормаль OpenGL и шероховатость уже подключены. Высота и AO остаются отдельными
картами для внешнего рендера; они не назначаются неподходящему старому UV-parallax
параметру Dom3D. Чтобы сохранить размер зерна, один UV-участок 0…1 должен
соответствовать заданной ширине/высоте в миллиметрах.
Пути PNG записаны относительно `.d3mat`; рендер ищет карты рядом с материалом.
Проект сохраняет исходный путь материала, поэтому после открытия `.dom3d`
связь с внешним пакетом остаётся. Сам пакет нужно хранить вместе с его PNG.

Это конечный **не бесшовный** участок. Автоматическое бесшовное повторение и
нативное процедурное вычисление в Cycles/CPU raytrace пока не реализованы.
Выпечка использует ту же GLSL-функцию, что и интерактивный материал.

GLSL 1.20 использует float hash: побитовая идентичность между разными GPU и
точность на чрезвычайно больших координатах не гарантируются.

## Проверки

`CatalogImportTests --test-procedural-material` проверяет параметры, старый
формат, drag-and-drop, библиотеку и проект. Вариант `--render` дополнительно
проверяет OpenGL, seed, влияние Relief, независимость от разбиения плоской
поверхности, возвращение камеры, применение параметра через диалог и сохраняет
снимки в `output/plaster`. Замеры кадра включают чтение framebuffer и не
являются чистым временем GPU.

Проверено 2026-09-05 на Intel UHD Graphics 770, 800×600: медиана / p95
с чтением framebuffer — обычный материал 4.13 / 4.37 мс, Preview
10.43 / 10.92 мс, High 11.50 / 13.19 мс. Это замер одной стены,
не гарантия производительности сложного интерьера. Пять тестов CTest
(PbrMaterialLibraryTests, ScenePersistence, SolidPrimitiveTool, TileTool,
ProceduralMaterial) и отдельная OpenGL-проверка прошли.

Дополнение: проверены экспорт 2048×2048, чтение `.d3mat`, воспроизводимость,
смена Seed, совпадение нормали с производными экспортированной высоты,
16-битная точность PNG и удаление неполного пакета при отмене. Для запуска:
`CatalogImportTests --test-procedural-material --render --bake-large`.
Сферы имеют сваренный UV-шов и полюсы по вертикали; диагностические открытые
кромки и общая прозрачность сцены не влияют на миниатюры.
