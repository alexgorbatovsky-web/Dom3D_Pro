# Отверстие одним кликом по грани

Статус: `Внедрено`  
Дата: 2026-09-02

## Сценарий

Включить «Отверстие» и один раз щёлкнуть по плоской грани тела.
Отверстие сразу создаётся **в точке клика**, открывается панель
параметров и показываются два редактируемых расстояния до кромок.
Отдельного выбора центра, первой и второй кромки и модального диалога нет.

Диаметр, режим «сквозное / глубина» и глубина берутся из последних
настроек. Слишком большой начальный диаметр уменьшается до расстояния
от точки клика до ближайшей границы: радиус получает двукратный запас.
Пользователь может затем изменить диаметр, глубину и расстояния.

Создание сразу записывается как одна операция `SolidHole` в историю тела
и одна команда Undo «Create hole». Открытая после создания панель редактирует
уже существующую операцию; отмена самого создания выполняется через Undo.

## Расчёт

- `OpenGLViewport::SelectAt`: точка клика получается пересечением луча
  соответствующего экранного пикселя с плоскостью выбранной грани,
  как в перспективном, так и в ортографическом виде. Сигнал
  `PlanarFaceClicked` передаёт эту точку инструменту без второго клика.
- `solid/HolePlacement.cpp`: сохраняются координаты точки в плоскости,
  учитывается ориентация нормали CAD-грани и проверяется попадание
  точки в материал. Центроид грани не используется для размещения.
- Кромки берутся только с выбранной грани. Расстояние измеряется до
  конечной CAD-кромки, не до её бесконечного продолжения.
- Первая опора — ближайшая к точке клика прямая кромка. Вторая — ближайшая прямая,
  не параллельная первой. Это исключает пару противоположных сторон
  вытянутого прямоугольника, не задающую положение центра по двум осям.
- Сохраняются исходные концы опор, знаки сторон, нормаль и два расстояния.
  Существующий параметрический пересчёт перемещает отверстие по размерам.
- `ToolRegistry::PrepareHoleOnFace` только готовит параметры;
  `ApplyHole` выполняет прежний параметрический Boolean Cut.
- `MainWindow` управляет выбором и панелью. Создание отложено до завершения
  события выбора грани, чтобы не менять её топологию внутри обработчика клика.

## Ограничения

Требуется тело с параметрической историей и плоская грань с двумя
непараллельными прямыми кромками. Если точка лежит в уже существующем
отверстии либо вне вогнутой грани, тело не меняется и выводится сообщение.
Для круглой грани без прямых кромок фиктивные опоры не создаются.

## Проверка

`HoleFacePlacement`: нецентральные клики в разных частях прямоугольника
с переключением ближайших кромок, обратная нормаль, наклонённая грань,
клик не в центре треугольника, неподдерживаемые круглые/криволинейные грани,
недопустимый клик в существующем отверстии и допустимый рядом с ним;
сквозное и глухое отверстия, объём,
допустимый начальный диаметр, перемещение по размеру, Undo/Redo,
сохранение и повторное выполнение истории после загрузки.

`PropertyPanelTests`: редактируемые параметры отверстия.

Финальный Release-прогон: `HoleFacePlacement`, `PropertyPanelTests`,
`CreateSketchSurface`, `LiveFilletValidation` — все четыре теста пройдены.
После уточнения размещения в точке клика `HoleFacePlacement` также пройден.
В первом общем прогоне `PropertyPanelTests` один раз завершился SegFault;
пять последовательных повторов прошли. Причина разового сбоя не установлена,
это не следует считать исправлением или подтверждением стабильности панели.
Приложение пересобрано. Интерактивная проверка клика в GUI остаётся
пользовательской проверкой; автоматические тесты проверяют геометрию,
историю операций и элементы панели.

```powershell
ctest --test-dir build -C Release -R 'HoleFacePlacement|PropertyPanelTests' --output-on-failure
```
