# Эскиз → изображение → модель в Dom3D Pro

## Что было сделано со стулом

Исходный рисунок содержал профиль и план сиденья. Imagegen создал концептуальное изображение по рисунку. Затем отдельный процедурный скрипт Blender построил геометрию по интерпретации рисунка и концепта: основание, подушку, ножки и спинку. Это не автоматическое извлечение точной геометрии из фотографии. Размеры, материалы и устройство спинки были выбраны при моделировании.

Артефакты примера находятся в `output/chair_concept`: исходный рисунок, концепт, скрипт, GLB, OBJ и Blender. Такой процесс уже можно использовать вручную: получить модель вне приложения, затем импортировать GLB.

## Предлагаемый первый этап интеграции

Окно «Создать по эскизу»: изображения спереди, сбоку, сверху (достаточно одного), описание, известные размеры. Эскизы и размеры сохраняются вместе с заданием. Если размер неизвестен, приложение показывает принятые значения до добавления объекта в сцену.

1. Получить концептуальное изображение через отдельный сервис генерации изображений. Пользователь может выбрать вариант или сразу перейти к моделированию по эскизу.
2. Для мебели преобразовать описание в структурированные параметры: тип деталей, размеры, профили, кривые, материалы, связи. Валидировать схему, диапазоны размеров и количество деталей.
3. Применить проверенные генераторы геометрии. Первым типом сделать стул: D-образное сиденье, подушка, две передние ножки, две изогнутые задние стойки и спинка. На прототипе можно запускать фиксированный скрипт Blender через QProcess и передавать параметры JSON. Существующий `BlenderCyclesRenderer` показывает, как приложение управляет процессом Blender; генератор должен быть отдельным компонентом.
4. Предпросмотр результата, проверка размеров и материалов, затем добавление в документ одной отменяемой операцией. Параметры и исходные эскизы сохранять для повторной генерации.

Для CAD-редактирования следующий шаг — создавать родные тела и поверхности Dom3D через существующие построители, вместо обмена только треугольной сеткой. Импорт GLB создаёт CMesh3D и сам по себе не восстанавливает параметрические операции.

## Произвольные формы

Второй путь — отдельный поставщик image-to-3D, возвращающий GLB. Подходит для предметов интерьера сложной формы. Провайдер выбирается после испытаний качества на собственных эскизах; наличие генерации изображения само по себе не означает наличие генерации 3D. Для этого пути нужны контроль масштаба, проверка сетки, ограничение числа полигонов и предпросмотр. Не обещать производственную точность по одному изображению.

## Границы компонентов

- `SketchGenerationRequest`: изображения, описание, единицы, известные размеры и выбранный способ моделирования.
- `ConceptImageProvider`: генерация/редактирование изображений.
- `ParametricFurnitureGenerator`: проверенная схема параметров и генераторы деталей.
- `ImageToMeshProvider`: необязательный внешний генератор сеток.
- `GenerationJob`: фоновые запросы, прогресс, отмена, повторы, сохранение результата без блокировки интерфейса.
- Предпросмотр: габариты, состав деталей, материалы; добавление в документ после выбора результата.

В приложение не встраивать произвольное выполнение сгенерированного Python. Для параметрического пути использовать собственные фиксированные генераторы с JSON-параметрами. Облачные ключи и оплата оформляются отдельно от локального импорта; секреты не хранятся в файле проекта.

## Реализованный импорт GLB

`GlbIO` использует общий с FBX преобразователь Assimp. Сборка включает glTF reader. «Import → glTF Binary (*.glb)» и перетаскивание файла вызывают один обработчик.

- Самодостаточные бинарные сцены glTF 2.0.
- Метры/Y-up преобразуются в миллиметры/Z-up: `(x, y, z) → (1000x, -1000z, 1000y)`.
- Учитываются вложенные матрицы узлов, повторные экземпляры и зеркальные преобразования.
- Примитивы материалов становятся отдельными CMesh3D; сохраняются имена и пути групп.
- Импортируются UV0, нормали, цвет, прозрачность, roughness/metallic, встроенные поддерживаемые Qt изображения и основные карты материалов.
- Для общей metallic/roughness-карты извлекаются отдельные grayscale-изображения из B/G каналов с применением соответствующих факторов. Кэш изображений сохраняется в AppLocalDataLocation/ImportedGLBTextures.
- Ошибка чтения не добавляет частично загруженную геометрию в документ.

Это статический импорт: анимация, скелетное воспроизведение, morph targets и расширенные материалы не представлены в модели данных Dom3D. Точная передача alpha MASK, отдельных UV-наборов/трансформаций для каждой карты и всех glTF-расширений не заявляется. Текстовый .gltf не входит в этот этап. Экспорт кухни в самодостаточный GLB описан в [glb-export.md](glb-export.md).

Проверки: `ExchangeIOTests` содержит генерируемый GLB с вложенными узлами, зеркальным масштабом, несколькими материалами, экземплярами и PNG внутри файла. Реальный файл проверяется командой `ExchangeIOTests --import-glb path/to/model.glb`.
