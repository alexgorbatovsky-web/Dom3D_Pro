## Фен: регрессия подготовки boundary

`Hairdryer.dom3d`, SHA256
`9CFC6ABAA75E5415184D17C282FE8F6FDB9DF97B933B1289F4763ECABA79A61B`.
`HairdryerCadBoundary` проверяет 85 charts основной и 283 charts второй оболочки,
неизменность CAD identity/допусков/pcurves, общий master и кэш.
Это проверка подготовки границ, а не passing-case готовой Mesh Quadro;

`HairdryerCadChartConsumer` проверяет следующий экспериментальный этап: 85 UV-входов,
85 принятых квадро-граней, исходные ориентированные CAD-рёбра и master XYZ,
замкнутость всего тела и клетки после перевода в float. Проверенный OBJ содержит
181 936 квадро-клеток; обычный UI пока не подключён. Диагностика описана в
[Вики](../../../docs/knowledge/mesh/hairdryer-cad-chart-consumer.md).

## Подушка-2: общие CAD-границы

`Podushka-2.dom3d`, тело `Extrude Solid`, 18 граней. `PillowCadQuadro` проверяет
плотности 0.25, 0.50, 1.00 и повторную 0.50: только четырёхугольники,
замкнутая ориентированная сетка, Эйлер 2, объём и принадлежность CAD-граням,
детерминизм и один topology snapshot на неизменное тело.
Визуальная проверка: [сетка сверху и снизу](../../../docs/knowledge/mesh/pillow-2-cad-quadro.md).

Эта папка содержит реальные проекты, на которых изменения Mesh Quadro должны
проверяться повторно. Оригинальный пользовательский файл копируется сюда и
защищается контрольной суммой, поэтому тест не зависит от содержимого рабочего
стола разработчика.

`cases.json` задаёт:

- имя и контрольную сумму проекта;
- режим построения;
- проверяемые значения Density;
- ожидаемое текущее состояние;
- известные проблемные поверхности.

Статус `known_failure` означает воспроизводимый, ещё не исправленный дефект.
Такой случай должен отображаться в отчёте отдельно и не может незаметно
исчезнуть из набора. После корректного исправления статус меняется на `pass`, а
ожидаемые характеристики сетки записываются заново только после визуальной
проверки.

Запуск корпуса после сборки `CatalogImportTests`:

```powershell
ctest --test-dir build -C Release -R MeshRegressionCorpus --output-on-failure
```

Проверка `known_failure` является характеристической: она подтверждает точный
известный профиль отказа. Если результат изменился, тест останавливается и
требует визуально проверить сетку перед обновлением ожиданий.

## Cylinder_Min_2_Cylinder: два выреза через периодический шов

Исходный пользовательский проект сохранён без изменений. SHA256:
`E627AC4E19969AC14033689A942C224047F6BC39827E68F4AE5A6FE348AD1787`.
Одно тело `Boolean Cut`, пять поверхностей; внешняя цилиндрическая грань
имеет двенадцать подготовленных рёбер.

`CylinderMultipleWindows` проверяет Density 0.35, 0.50, 0.65, 0.80, 1.00
и повторно 0.50, с SLX и без него. Проверяются индексы, конечные координаты,
ненулевая площадь ячеек, связность поверхностей, четыре граничных цикла
внешнего цилиндра и замкнутость манифолдной сетки после сварки.
При 0.50 исправление уменьшило число открытых рёбер со 104 до нуля.

Density 0.20 и 0.25 пока имеют отдельный дефект разрезания крупных ячеек;
прохождение теста не означает исправление этих плотностей. Ограничений
на выбираемую пользователем плотность не добавлено.

Подробности: [два цилиндрических выреза](../../../docs/knowledge/mesh/trimming/cylinder-two-seam-windows.md).

## Boolean_Fill

`Boolean_Fill.dom3d` первоначально воспроизводил отказ двух трёхсторонних
сплайновых патчей с вырожденной четвёртой кромкой. С 2026-09-02 нормали
восстанавливаются по соседним производным: перестроение успешно на всех пяти
плотностях, пустых поверхностей нет. Статус
`normal_failure_fixed_topology_pending` намеренно не равен `pass`: на Density
0.50 остаются 14 открытых рёбер поверхности 38. Корпус проверяет только успешное
перестроение и отсутствие пустых поверхностей, не полную корректность топологии.
Подробности находятся в Wiki:
[Boolean_Fill: сингулярные B-Spline-поверхности](../../../docs/knowledge/mesh/trimming/boolean-fill-singular-bspline.md).

Рядом хранится `Boolean_Fill-export.step` — экспорт той же итоговой геометрии.
3DCoat успешно завершает по нему квадро-сетку. На сложных стыках зализов сетка
локально нерегулярна, но не остаётся пустой. STEP и снимки результата служат
внешним референсом: дефект локализован в алгоритме Dom3D, а не является
доказательством непригодности самой формы для квадрангуляции.

## Extrude_SL: вырожденный остаточный фронт

`Extrude_SL.dom3d` — неизменённая копия пользовательского проекта с двумя телами
(8 и 18 поверхностей). SHA256:
`202F5D566A311DFA62A348E86D1ECDA3C9F3287111A620A3AA52DE27C78231D7`.

При Density 0.25 передняя плоская грань второго тела строилась около 35 секунд:
квадрангулятор сплющивал остаточный контур вдоль прямой границы, затем создавал
нулевые полосы и повторял неизменные попытки до лимита 5000 итераций. После
сборки оставались три несвязанных фрагмента и незамкнутые швы.

Проверка площади каждого остаточного кольца отклоняет такой шаг до его принятия.
Когда классификация углов больше не меняется, цикл завершается без повторения
тех же кандидатов. Остальной алгоритм построения и сглаживания сохранён.

Отдельный тест `ExtrudeSlQuadro` проверяет обе модели на Density 0.20, 0.25,
0.30, 0.35, 0.50 и повторно 0.25: только четырёхугольники, без аварийного перехода,
одна компонента на поверхность, отсутствие открытых/немногообразных швов после
сварки. Для второго тела дополнительно проверяются Density 0.65, 0.80 и 1.00:
число подготовленных узлов и вершин сваренной сетки должно возрастать на каждом
шаге. Тайм-аут теста — 60 секунд на все пятнадцать перестроений.

```powershell
ctest --test-dir build -C Release -R ExtrudeSlQuadro --output-on-failure
```

При Density 0.50 обнаружен ещё один вырожденный фронт: положительная площадь
остаточной полоски была меньше точности исходных float-координат, но проходила
double-допуск 1e-10. После остановки незакрытого фронта сглаживание расширяло
полоску в видимую щель. Допуск площади теперь относительный, на уровне epsilon
входного float; знак угловой нормали проверяется без подстановки +Z для малых
векторных произведений. Входная линия и триангуляция не изменяются.

Ограничения Density 0.50 для тел с 16 и более поверхностями и 27 точек на
подготовленное ребро сняты. У второго тела при Density 0.50 / 0.65 / 0.80 / 1.00
получается 1723 / 2496 / 3870 / 6805 вершин сваренной замкнутой сетки.

### Fill Contour: перенос в Tools_Mesh3D

`Extrude_SL_Boundary_UV_D050.txt` — одна диагностическая UV-полилиния из
60 узлов, переданная в Fill Contour при Density 0.50, без умножения U на радиус.
Тест `ToolsMesh3DFillContour` сравнивает новый инструмент с прежней цепочкой
вызовов для Raw и обычного режима: координаты входа, OBJ треугольников и
итоговой сетки должны совпадать. Также проверяются перезапись единственного
контура, точность TXT, повторная конечная точка и ошибки записи диагностики.
Дополнительно тест проверяет отсутствие внутренних открытых рёбер, сохранение
всех 60 граничных рёбер, связность, положительную площадь четырёхугольников и
совпадение общей площади с контуром. Проверки повторяются при изменении масштаба
всех координат и отдельно U (включая U * 2 для исходного цилиндра).

```powershell
ctest --test-dir build -C Release -R ToolsMesh3DFillContour --output-on-failure
```
