# Mesh regression corpus

Эта папка содержит реальные проекты, на которых изменения Mesh Quadro должны
проверяться повторно. Оригинальный пользовательский файл копируется сюда и
защищается контрольной суммой, поэтому тест не зависит от содержимого рабочего
стола разработчика.

`cases.json` задаёт:

- имя и контрольную сумму проекта;
- режим построения;
- проверяемые значения Density;
- ожидаемое текущее состояние;
- известные проблемные поверхности.

Статус `known_failure` означает воспроизводимый, ещё не исправленный дефект.
Такой случай должен отображаться в отчёте отдельно и не может незаметно
исчезнуть из набора. После корректного исправления статус меняется на `pass`, а
ожидаемые характеристики сетки записываются заново только после визуальной
проверки.

Запуск корпуса после сборки `CatalogImportTests`:

```powershell
ctest --test-dir build -C Release -R MeshRegressionCorpus --output-on-failure
```

Проверка `known_failure` является характеристической: она подтверждает точный
известный профиль отказа. Если результат изменился, тест останавливается и
требует визуально проверить сетку перед обновлением ожиданий.

## Первый случай

`Boolean_Fill.dom3d` воспроизводит отказ двух трёхсторонних B-Spline-патчей с
вырожденной четвёртой кромкой. Подробности находятся в Wiki:
[Boolean_Fill: сингулярные B-Spline-поверхности](../../../docs/knowledge/mesh/trimming/boolean-fill-singular-bspline.md).

Рядом хранится `Boolean_Fill-export.step` — экспорт той же итоговой геометрии.
3DCoat успешно завершает по нему квадро-сетку. На сложных стыках зализов сетка
локально нерегулярна, но не остаётся пустой. STEP и снимки результата служат
внешним референсом: дефект локализован в алгоритме Dom3D, а не является
доказательством непригодности самой формы для квадрангуляции.
